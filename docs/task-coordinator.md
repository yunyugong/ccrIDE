# 任务调度（0.3.7）

每次执行分配一个随机的 128 位任务 ID，编译、运行、自动检查、测试中的每个程序、GDB 和新版 AI/clangd 服务统一使用 execution::Run。编译并运行的两个阶段各有一个 ID；尚未实现整条流水线的父任务 ID 或任务依赖图。

## 查看和取消

“运行 → 任务管理”展示当前数据目录中最近 200 个任务，可查看状态、排队/执行时间、实际工作目录、退出码，停止指定任务并打开记录目录。取消排队任务不会启动目标程序；取消运行任务沿用 Job 整树回收。测试中取消某个程序也会停止所属测试批次。服务被停止后由相应插件显示失败，需要重新启用服务。

当前只列出本数据目录的记录；不同便携安装共享并发名额，但不会自动汇总各自的日志。取消通道使用任务 ID，可跨 IDE 实例。实例异常退出的记录显示“实例已退出”。

## 并发名额

| 类别 | 同时运行上限 | 包括 |
|---|---|---|
| 前台 | 2 | 编译、用户程序、样例/对拍、GDB、其他工具调用 |
| 后台检查 | 1 | 自动语法检查、头文件路径查询 |
| 常驻服务 | 2 | AI 与 clangd |

同一 Windows 登录会话、同一用户的新版 IDE 与新版服务插件共享具名互斥名额。实例崩溃后 Windows 释放其拥有的名额；不会因为进程退出留下永久占用。每次任务仍有独立的 Job、输入管道、输出限制和取消事件。

排队默认最多 30 秒，到期报告“排队超时”；程序运行时限从取得名额并启动阶段开始计算，排队不消耗该时限。惰性的头文件路径查询只等待名额 100 ms，繁忙时采用现有目录布局兜底。当前固定名额，不提供可配置上限、严格 FIFO 或优先级抢占。GDB 暂停期间仍占前台名额，常驻服务运行期间占服务名额。

这是受管理根任务的并发限制；每个 Job 内最多 128 个进程，不能将其理解为全系统只有 5 个进程。内存限制按任务 Job 计算，尚未实现跨任务总内存预算。

AI 与 clangd 插件更新到 1.2.0，清单标记 taskCoordinatorVersion=1。旧版这两个插件会显示升级提示而不加载。该标记仅是兼容约定；任意原生 DLL 仍可自行创建进程或阻塞 UI，本批没有实现 DLL 安全沙箱。

## 独立目录

默认记录位置为 data/tasks/<ID>/：

- work/：用户程序的默认工作目录。
- tmp/：默认 TEMP/TMP，仅覆盖子进程环境。
- task.json：命令参数、状态、耗时、退出码和实际目录。
- stdout.bin、stderr.bin：受既有输出上限约束的原始输出，按字节保存，未必是 UTF-8。
- .claimed：防止同一任务上下文被重复执行。

子进程还会收到 CCRIDE_TASK_ID 和 CCRIDE_TASK_DIR。显式 TEMP/TMP 环境覆盖保留；并行程序的默认相对文件名和临时文件互不覆盖。编译保持源码目录为 cwd，兼容相对 include；检查使用独立源码快照，编译日志不再共用 build_out.txt/build_err.txt。

编译、测试程序和 clangd 驱动探测分别将所选工具链 bin 加入其子进程 PATH；无需依赖开发机的系统 PATH，也不修改系统设置。

设置 → 运行与资源限制 →“每次运行使用独立工作目录”默认开启；填写“运行目录”优先采用该目录。关闭后可恢复在源码目录运行，适用于读取源码旁 input.txt 的旧程序。显式指定目录或关闭隔离后，相对文件重名需要用户自己协调。测试采用同一隔离开关；测试输入依然由 stdin 发送。

GDB 与被调试程序共用该次工作目录；未指定输入文件时的空 stdin 文件也在该次任务目录内。AI 与 clangd 不保存协议 stdout/stderr，也不将标准输入或环境覆盖值写入任务记录；命令参数和程序输出可能包含个人信息，分享前应检查。

记录与 work/tmp 文件保留，便于查看运行产生的文件；当前没有自动清除或磁盘总配额，建议关闭 IDE 后定期清理不需要的 data/tasks。安装包会剔除验证时生成的任务记录，不分发本机日志。

## 验证

CTest 的 ccrIDE_tasks 覆盖：两前台名额、独立后台名额、排队取消/超时、排队时间不计入运行时限、同名文件隔离、TEMP/任务环境、保留显式目录、禁止重用 ID、回调失败回收、协议日志关闭、跨进程共享名额、持有者强制退出后的名额恢复与子进程退出。既有执行、测试、调试与插件测试继续运行。

这不是文件/网络权限隔离；多个 IDE 实例共用设置、恢复文件和编译产物索引的完整合并机制也不在本批范围内。
