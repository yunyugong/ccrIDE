# 0.3.6 可靠性改进

## 恢复备份

原实现把当前 workspace.json 直接复制到 .previous；当前文件损坏时，再次保存可能用损坏内容覆盖有效备份。本版仅轮换能够完整解析和校验的主快照，备份先写临时文件，再提交；主文件替换失败时仍保留有效前代。新增锁住主文件导致替换失败、损坏后再次保存及再次损坏的检查。

恢复读取也会校验编码、坐标和滚动数据；光标对齐 UTF-8 字符边界，断点限制在有效行内并去重。仍只恢复副本，不自动覆盖源码。不是跨多个 IDE 实例的恢复合并系统，也不承诺抵抗磁盘/硬件永久故障。

## 测试证据与结果

测试、对拍现在从归档中的主文件快照编译，保存 SHA-256 和实际编译参数，避免“归档内容与随后修改的主文件不同”。相对包含目录和工作目录保留原源文件语义；头文件、工具链及外部资源仍没有整体冻结，不能把主文件快照等同于完整工程镜像。

任务清单记录 Subtask 分值/依赖与样例计划的摘要。schema 2 在正常完成、编译失败、取消及其他错误后都提交终态；清单采用临时文件替换，并保存实际结果与错误。数据文件与生成的 EXE 共同预算 510 MiB（EXE 在编译结束后核算，编译期间没有文件系统硬配额），最终清单另保留 2 MiB，总预算仍为 512 MiB；文件系统拒绝写入时会明确报错，无法保证该情况下仍成功落盘。

每例新增 processes.json，记录各角色的命令参数、工作目录、启动状态、退出码、终止原因、耗时及峰值内存。界面结果详情显示退出码（十进制/十六进制）与终止原因；生成器和参考解失败也保留正确的耗时、退出码。二进制或非法 UTF-8 输出的差异片段使用转义字节，避免结果 JSON 因差异文本编码损坏而写入失败。

## DLL 加载边界

加载前检查 PE 文件头和 x64 架构，不扫描插件目录链接，不加载链接形式的 DLL；重复 ID（忽略 ASCII 大小写）的插件不会初始化。依赖通过 DLL 自身目录及系统/应用允许目录解析，不依赖当前工作目录。缺少依赖会显示加载失败。

新增真实 DLL 测试：插件目录中的依赖返回 1，当前目录同名文件返回 2；验证实际加载值为 1，删除合法依赖后也不回退到当前目录。另检查重复 ID 与伪造 x86 文件头。

以上是加载正确性和防误加载措施。任意原生 DLL 仍在宿主进程内执行；完整权限系统和原生 UI 插件进程隔离仍未完成，不能把这些检查视为沙箱。
