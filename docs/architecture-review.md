# 架构核对与后续验收

核对日期：2026-11-07。本文区分当前实现与后续计划，计划不代表已经落地。

## 当前定位

ccrIDE 是 Windows 上轻量、单文件优先的 C++ IDE。高级调试、测试框架集成、大型项目管理尚不完整；重型模板元编程、宏和条件编译可能超出当前补全模型的能力。不能将存在接口写成专业工作流已经完成。

## A. 插件加载与隔离

外部 DLL 的 Plugin_OnLoadV2、Plugin_OnFrame、Plugin_OnUnload 都在 IDE 进程内运行，共享 ImGui 上下文。AI 1.1.0 的网络请求与接口响应解析已迁到独立服务进程，完成取消、超时和服务故障检查；UI DLL 和客户端协议验证仍在主进程。这不构成所有插件的隔离或权限沙箱。详见 [第一阶段实现与限制](process-services.md)。注释插件同样在进程内。插件崩溃、内存损坏、死循环仍可能影响整个 IDE。

后续采用混合架构：可信的简单 UI 扩展可在进程内；语言服务器、AI 服务、编译分析与第三方服务使用独立进程。宿主绘制 UI，通过结构化消息获取结果。权限限制需另行设计与验证，独立进程和 Windows Job 都不能直接等同于安全沙箱。

进程外服务验收：

- 协议版本、请求 ID、取消与超时；限制消息大小、并发和每帧消费预算。
- 注入崩溃、无响应、输出洪泛、畸形消息时，编辑、保存、编译仍可用。
- 显示故障与重启入口；停用、卸载和退出时回收进程与请求。
- 自动重启有次数上限；日志不记录凭据或整段私有请求。
- 故障测试通过前，不宣称已经实现插件隔离。

## B. 补全边界

核心保留轻量模型，继续修复基础作用域和真实 include 的补全错误，不以重写完整 C++ 编译器为目标。

工程语义由独立 clangd 插件承接，已实现文档打开/变更/关闭同步、编译命令配置、过期请求丢弃、取消和诊断/补全映射。未安装、启动失败或停用插件时，基础编辑与轻量补全仍可用。首版已在 0.3.4 实现；见 [配置与验收范围](clangd.md)。

验收使用嵌套模板、别名、宏、条件编译、多翻译单元与真实工程样本，记录正确性、延迟和资源占用。

## C. 工作流完成度

| 领域 | 已有基础 | 待完成或验证 |
|---|---|---|
| 调试 | 单目标 GDB/MI、断点、局部变量、栈、求值 | 线程管理、寄存器、反汇编、异步命令反馈、工具链兼容 |
| 测试 | 项目自身的回归检查、单文件运行和资源管理 | IDE 内样例比较、归档、工程测试框架发现与执行 |
| 恢复 | 当前标签自动保存、已有路径的会话恢复 | 全部未保存标签独立快照、原子写入、故障恢复选择、不覆盖原文件 |
| 工程 | 多标签、文件树 | 多目标模型、构建配置 UI、完整跨工程语义和测试管理 |
| 插件 | 加载、启停、本地 ZIP、独立 AI/注释包 | 故障隔离、稳定协议、升级回滚、依赖和平台兼容管理 |

按新建、配置、执行、失败、取消、退出恢复的完整路径验收。现有自动检查仅证明其覆盖范围，不证明上表全部完成。
