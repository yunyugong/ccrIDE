# 进程外服务：第一阶段

当前实现用于 AI 网络服务的故障约束，不是任意原生插件的权限沙箱，也不是完整的语言服务器宿主。

## 结构

AI UI 插件仍是进程内 DLL，只负责设置、历史、编辑器选区和绘制。每次发送或测试连接，后台线程通过 service::Call 启动插件目录中的 ai-service.exe。HTTP、SSE 与接口响应解析在该进程中执行。每次请求完成进程即退出；重试启动新进程，没有自动重启循环。

凭据与请求正文只走子进程 stdin 管道，不放入命令行参数、环境覆盖或临时文件，不记录原始通信日志。传给模型的选中代码仍由用户开关控制。

通信层在 src/service_client.h/.cpp，进程/管道/Job 复用 execution::Run。主 UI 线程不等待网络请求。取消、超时、卸载插件和退出时终止服务及受管子进程，随后回收工作线程。服务故障显示错误，可再次发送；失败或取消的半条回复不加入成功对话历史。

## 协议 v1

每个进程接收一个 UTF-8 JSON 请求，stdin 结束表示请求完整。字段为 v=1、单调请求 id、method、payload。AI 方法为 chat 和 models。

stdout 使用逐行 JSON：每帧携带相同 v/id，type 为 text 或 done。text 提供增量文本；done 提供 ok/error。客户端校验版本、ID、类型、字段、JSON/UTF-8 和结束状态，拒绝 done 后的额外消息、截断消息、异常退出和未完成响应。

- 输入上限 2 MiB，超限不启动服务。
- 单帧上限 256 KiB；无换行输出也不能无限累积。
- stdout/stderr 合计上限 8 MiB，服务 Job 提交内存上限 256 MiB。
- AI 请求默认 120 秒，测试连接 30 秒；通用超时限制为 0.1–300 秒。
- AI 同时只执行一个请求；此阶段不提供通用多服务任务调度。
- stderr 不直接显示，不将畸形消息或进程 stderr 原文拼接进错误提示。

超限、协议错误或取消后清理 Job。Windows Job 控制资源和进程生命周期，不限制服务账户本身的文件/网络权限。

## 验证

service_faults 检查正常 UTF-8、异常退出、无响应、取消、错误 ID、畸形 JSON、单帧超限、输出洪泛、缺少结束帧、完成后额外输出与错误退出码。每个失败后再次请求健康服务。

AI mock 检查鉴权、非流式/流式中文、多轮历史、选区、停止和卸载；另在请求中终止本测试进程创建的 ai-service.exe，检查错误反馈与后续正常重试。

这些检查证明相应服务故障路径，不保证任意进程内 UI 插件出错时 IDE 不受影响。
