# 统一执行管理：本批实现与验证

2026-11-07 更新：执行后端已供测试、对拍、GDB 和服务复用；0.3.7 接入任务 ID、独立目录与跨实例并发限制，详见 [任务调度](task-coordinator.md)。

## 使用方式

设置 → 运行与资源限制：

| 设置 | 默认值 | 含义 |
|---|---|---|
| 运行时间 | 60000 ms | 墙钟时间，设置范围 100..3600000 ms |
| 运行内存 | 256 MiB | 同一任务进程组的总提交内存；0 为不限制，最大 16384 MiB |
| 总输出 | 16 MiB | stdout 与 stderr 合计，范围 1..64 MiB，超过即终止并报告 OLE |
| 编译时间 | 120000 ms | 可配置；编译输出独立采用 16 MiB 上限 |
| 程序参数 | 空 | Windows 参数转义规则，支持空参数、引号、尾部反斜线、中文 |
| 运行目录 | 每次任务的独立目录 | 可显式指定目录或关闭隔离；无效目录会报告系统错误 |
| 环境覆盖 | 空 | 每行 NAME=value，只传给目标程序，不修改 IDE 环境 |

停止按钮和菜单可取消编译及运行。退出 IDE 也会取消当前编译/运行及自动检查，再等待线程回收。编译与运行日志展示命令、目录、限制、耗时和退出原因；运行显示峰值提交内存，常见访问冲突和栈溢出有补充说明。环境覆盖值可在设置中查看，不默认写入控制台；其本机会存入 settings.json，注意不要把包含凭据的设置直接分享。

编译和运行日志按任务 ID 保存到 data/tasks，不再共用 build_out.txt / build_err.txt。AI 与 clangd 协议输出不落盘；详情见任务调度说明。

## 代码结构

- `src/execution.h/.cpp`：同步工作线程接口 `execution::Run(Request)`，集中负责进程创建、句柄、Job、管道、资源限制、取消与回收。不能在 UI 线程调用；回调同样不得阻塞。
- `Request`：exe、argv、cwd、环境覆盖、限制、输入文本/交互回调、输出回调、取消标志。
- `Result`：是否启动、结束原因、原始退出码、耗时、观测峰值提交内存、输出字节数、stdout/stderr 和具体错误。非零退出码与资源终止原因分别保留；这是执行结果，不是完整的测试判题系统。
- `utils::RunProcess`：兼容原有工具调用，改为调用统一执行器并保存有界日志。后台检查、头文件工具查询、插件源码编译因此共用同一后端。
- `App::StartCompileRun`：在主线程快照参数、限制与编辑代数，后台执行。手动编译诊断独立于自动检查开关。

## 清理与边界

先建立并配置 Windows Job，再挂起创建进程，限制继承句柄为本任务的三个输入输出句柄。确认进程加入 Job 后才恢复执行。建立、配置、加入或恢复失败时不执行目标代码；已创建的挂起进程会被回收并返回错误。

停止、超时、资源终止和正常主进程退出均清理同一 Job 的后代。不允许 breakaway，每个任务至多 128 个进程。除查询 Job 活动进程数外，还持有已观测后代的同步句柄并等待退出，避免成员计数为零但后代尚未完成退出的时序误判。清理等待有上限，失败会显式报告。

stdin 使用支持 overlapped I/O 的管道，目标不读取时不会把执行线程卡在同步写入。stdout/stderr 每轮各读取至多 64 KiB，每次至多 8 KiB，轮次间检查取消与超时。文本输入发送完成后关闭写端提供 EOF；当前 IDE 面板仍是交互输入，上层文件/样例输入切换留待下一批。

执行总输出字节限制、显示队列和控制台保留量分别管理：队列至多 1 MiB，控制台文本至多 8 MiB 且至多 6000 条记录；满载保留最新内容并提示省略，结束状态不会排在被丢弃的新输出中。待发送交互输入另有队列上限。输出显示省略不等于 OLE。

内存限制是 Job 的提交内存限制，不是工作集/RSS；内存错误的识别依赖系统通知和程序行为。Windows 不保证所有 Job 完成端口通知均送达，因此不能保证每一次内存申请失败都分类为 MLE；原始退出码和日志仍保留。程序正常退出时，仍会终止其未退出的后代。

这些机制面向 Windows 普通本地进程的资源管理，不是恶意代码安全沙箱，也不限制文件或网络权限。基础依据见 Microsoft 的 [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 与 [启动属性列表](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-initializeprocthreadattributelist) 文档。

## 可复验的测试

构建后运行 CTest，包含 `MiniCPP_regression` 和新增 `MiniCPP_execution`。后者使用本地测试辅助程序，不运行用户程序，也不写用户配置。

- 文本 stdin 与 EOF、stdout/stderr 分离和合计上限、精确达到上限、连续无换行输出、输出时取消。
- 目标不读取大段 stdin 时取消、墙钟超时、提交内存超限、非零退出、访问冲突。
- 中文/空格可执行路径、中文工作目录、环境覆盖、空参数/空格/引号/尾部反斜线、并发任务的输入输出互不干扰。
- 父子孙三层进程在超时、手动停止和父进程主动退出后全部结束。
- 无效工具或目录；仅测试构建可注入 Job 创建/配置/分配与恢复失败，检查目标未执行。发布构建不含故障注入入口。
- 重复执行后的句柄数量、输出队列/控制台边界、配置往返/旧配置默认值/无效值收敛。
- IDE F5 实际编译成功运行、编译报错、自动检查关闭时保留编译诊断、取消编译。

任务调度、GDB、样例/对拍的当前验证另见对应文档；未覆盖全部系统 API 故障组合，纯核心冷启动性能仍需单独测量。
